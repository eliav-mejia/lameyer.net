Release 1.0.1 — WhatsApp chat widget

Floating contact box on the home page that opens a pre-filled wa.me conversation per region.

1Summary

1.0.1 adds a floating WhatsApp chat launcher to index.html. A visitor opens the panel, picks a region (Mexico or Spain today), edits a pre-written greeting and presses Iniciar chat, which opens https://wa.me/<number>?text=<message> in a new tab. No message passes through any Lameyer server: the widget only builds a link.

It is the only component of the site written as plain JavaScript (an IIFE) rather than JSX, which makes it the easiest piece to move into the 1.2.0 JavaScript codebase, and also the piece most likely to drift because it exists in two copies.

3How it works

3.1 Configuration

index.html · widget script

var REGIONS = [
    { code: 'MX', dial: '+52',  number: '525610074750', text: 'Hola Lameyer, me gustaría información sobre sus servicios.' },
    { code: 'US', dial: '+1',   number: '',             text: 'Hi Lameyer, I would like information about your services.' },
    { code: 'ES', dial: '+34',  number: '34602557685',  text: 'Hola Lameyer, me gustaría información sobre sus servicios.' },
    { code: 'IL', dial: '+972', number: '',             text: 'Hi Lameyer, I would like information about your services.' }
];
var VALID = /^[1-9]\d{7,14}$/; // E.164 without "+": 8–15 digits, no leading zero
  • Numbers are digits only, international format, no +, spaces or trunk 0.
  • A region whose number is empty or fails VALID is dropped. An invalid (non-empty) number logs [lm-chat] Invalid WhatsApp number for … to the console.
  • If no region survives, the widget stays hidden and logs a warning. With one region, the region picker is hidden.

3.2 Region preselection

The default region is guessed from Intl.DateTimeFormat().resolvedOptions().timeZone:

Time zone patternRegion
Asia/Jerusalem, Asia/Tel_AvivIL (hidden until a number is set)
Europe/Madrid, Atlantic/Canary, Africa/CeutaES
12 Mexican America/* zones (Mexico_City, Cancun, Tijuana, …)MX
Any other America/*, Pacific/HonoluluUS (hidden until a number is set)
Anything else, or a hidden regionFirst visible region (MX)

3.3 Behaviour

  • Message: switching region replaces the text with that region's greeting until the visitor types; after the first input event (edited = true) their text is kept.
  • Link: link() rebuilds start.href on every change; the text is passed through encodeURIComponent. An empty message produces a bare wa.me/<number> link.
  • Opening: the anchor uses target="_blank" with rel="noopener noreferrer".
  • Stacking: z-index: 90 — above page content, below the mobile menu.

3.4 Accessibility

  • Launcher exposes aria-expanded, aria-controls="lm-chat-panel" and a label that switches between “Abrir” and “Cerrar”.
  • Regions are a role="radio" group with roving tabIndex and arrow-key navigation.
  • Esc closes the panel; focus moves to the start button on open and back to the launcher on close.

5Known issues and limits

5.1 Two copies, two more number sources. The widget code lives in index.html and whatsapp-chat-snippet.html; the Spanish number 34602557685 is also hard-coded in SELLER.whatsapp in js/tienda.jsx (1.0.2). Changing the number means editing three places.
  • 5.2 Home page only. No other page loads the widget. On /pages/components/ it would sit on top of the floating cart button (both are fixed at 24px from the bottom-right corner).
  • 5.3 Outside the component system. The widget does not use layout.jsx, Tailwind or site.css; its ~56 lines of CSS are inline in the page.
  • 5.4 innerHTML builds the region buttons from REGIONS. Safe while that list is hand-written config; it must not be fed from user or remote data.
  • 5.5 No analytics. Chats started are not counted, so there is no way to tell which region or page converts.
