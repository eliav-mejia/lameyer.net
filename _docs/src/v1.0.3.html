Release 1.0.3 — Product photos

1Summary

Each product card now shows a square photo on a white background instead of its category emoji. Photos are served in two widths and chosen by the browser, load lazily below the first row, and reserve their space so the grid does not shift. All photos come from Wikimedia Commons; the CC BY / CC BY-SA licences require attribution, so the shop gains a “Créditos de imágenes” list. Because several photos show a similar rather than the exact part, the shop footer and the terms page (section Productos) state that images are illustrative.

3How it works

3.1 Naming contract

/img/productos/<product.id>-400.webp     // card src, cart thumbnail
/img/productos/<product.id>-800.webp     // 2x / wide screens via srcset

A photo is shown only when IMAGE_CREDITS[product.id] exists. The file name is never checked: a credit entry without files gives a broken image; files without a credit entry are ignored and the emoji stays.

3.2 ProductImage

pages/components/index.html · line 120

<img src={`${base}-400.webp`}
     srcSet={`${base}-400.webp 400w, ${base}-800.webp 800w`}
     sizes="(min-width: 1024px) 340px, (min-width: 640px) 45vw, 90vw"
     width="400" height="400"
     loading={eager ? 'eager' : 'lazy'} fetchpriority={eager ? 'high' : undefined}
     decoding="async"
     alt={`${product.name} compatible con ${product.compat}`} />
  • Eager first row: ShopPage passes eager={i < 3}, matching the three-column desktop grid, so the likely LCP image is not lazy.
  • No layout shift: explicit width/height plus aspect-square.
  • Thumbnail (size="thumb"): 56×56 in the cart, always the 400 file, empty alt because the name is next to it.
  • Fallback: no credit entry → category icon in a grey square (currently of-hinge-5490, the hinge pair).

4Adding or replacing a photo

  1. Crop square, put on white, export <id>-400.webp and <id>-800.webp at quality ~80 into img/productos/.
  2. Add IMAGE_CREDITS['<id>'] with author, licence, licence URL and the Commons file page.
  3. Check the card, the cart thumbnail and the credits list.

5Known issues and limits

  • 5.1 Manual pipeline. Cropping, background and WebP export are done by hand; tools/ exists but is empty.
  • 5.2 Shared stand-in photos. Three pairs reuse one source image: both USB-C chargers, both iPhone batteries (a CAT B25 battery), and the iPhone 13 / Galaxy A54 screens (a Fairphone 2). Covered by the illustrative notice, but they are the first to replace with real stock photos.
  • 5.3 No existence check between IMAGE_CREDITS and the files on disk.
  • 5.4 One format. WebP only, no AVIF; acceptable for the browsers the site targets.
5.5 Unreleased data layer already in the folder. After the 1.0.3 entry was written, public/db/productos.json (30 products) and public/db/categorias.json (6 categories), schema lameyer.shop/v1, were added. Nothing loads them yet. They duplicate PRODUCTS, CATEGORIES and IMAGE_CREDITS with extra fields (slug, sku, stock, active, description, specs, compatible_models, image.*). Their _note points to public/db/README.md, which does not exist. Until the page reads them, edits must be made in both places.
