1Resumen y alcance

1.0.5 consolidó todo lo anterior y dejó libre la versión 1.0.6, que el documento 5 ya reservaba para la base de seguridad (su nota del §9 sobre el número de versión queda resuelta). 1.0.6 tiene dos partes:

Parte A · Desarrollo

Agente de IA aislado en un Dev Container, hooks de Git que no se pueden saltar en silencio y reglas en GitHub que sí bloquean. Especificado en el documento 5; aquí se resume (§3).

Parte B · Sitio público

DNS y proxy de Cloudflare, HTTPS estricto, cabeceras de seguridad, CSP, integridad de scripts, formularios, pedidos por WhatsApp, terceros y datos en el navegador (§4).

Puerta · Supabase

Solo con A y B en marcha se crea el proyecto Supabase, se sustituyen las cuentas de staging y se aplican las reglas de credenciales e IAM (documento 5, §8).

4Parte B · Sitio público

4.1 Cloudflare delante de GitHub Pages

  1. Añadir lameyer.net a Cloudflare (plan gratuito) y cambiar los NS en Namecheap a los que asigne Cloudflare.
  2. Registros A/AAAA de GitHub Pages y CNAME www con proxy activado (nube naranja). Ningún registro sin proxy que apunte al origen.
  3. SSL/TLS en Full (strict); «Always Use HTTPS»; TLS mínimo 1.2.
  4. DNSSEC en Cloudflare y el registro DS en Namecheap.
  5. CAA solo para las autoridades que use Cloudflare para el certificado del edge (Cloudflare las añade al activar CAA) y la de GitHub Pages (Let's Encrypt).
Verificar en la migración. GitHub Pages emite su certificado por desafío HTTP. Mantener los registros sin proxy hasta que GitHub muestre el certificado como emitido y comprobar después de activar el proxy que «Enforce HTTPS» sigue disponible y que la renovación funciona.

4.2 Cabeceras de seguridad

GitHub Pages no permite cabeceras propias, así que se añaden en Cloudflare con una regla de Transform Rules → Response Header Modification para todo el host:

Strict-Transport-Security: max-age=300                       // subir a 31536000 tras una semana sin incidencias; luego includeSubDomains
X-Content-Type-Options:    nosniff
Referrer-Policy:           strict-origin-when-cross-origin
Permissions-Policy:        camera=(), microphone=(), geolocation=(), payment=(), usb=()
X-Frame-Options:           DENY                               // equivalente a frame-ancestors 'none' para navegadores antiguos
Cross-Origin-Opener-Policy: same-origin

geolocation=() no afecta a la elección de país: el sitio usa la zona horaria y la IP, nunca la API de geolocalización del navegador.

4.3 Content-Security-Policy

Mientras Babel compile el JSX en el navegador, la CSP necesita 'unsafe-inline' y 'unsafe-eval' en script-src, lo que le quita la mayor parte de su valor contra XSS. Plan en dos pasos:

PasoPolítica
1 · Ahora, Report-OnlyLista de orígenes reales para descubrir dependencias olvidadas sin romper nada (abajo).
2 · Con buildTras la opción A o B de 1.0.5 (JSX compilado, Tailwind generado): script-src 'self' sin unsafe-*, aplicada (no Report-Only).

Content-Security-Policy-Report-Only (paso 1)

default-src 'self';
script-src  'self' 'unsafe-inline' 'unsafe-eval' https://cdnjs.cloudflare.com https://cdn.tailwindcss.com;
style-src   'self' 'unsafe-inline' https://fonts.googleapis.com;
font-src    https://fonts.gstatic.com;
img-src     'self' data: https://cdn.simpleicons.org https://images.unsplash.com https://placehold.co https://raw.githubusercontent.com;
connect-src 'self' https://api.frankfurter.dev https://get.geojs.io https://script.google.com https://script.googleusercontent.com;
form-action 'self';  base-uri 'self';  object-src 'none';  frame-ancestors 'none';
report-uri  https://<endpoint-de-informes>

El endpoint de informes puede ser un Worker de Cloudflare que guarde las violaciones en Workers Analytics Engine. CI añade una regla a checks.sh (doc. 5 §4.4) que falla si aparece dangerouslySetInnerHTML, innerHTML =, eval( o new Function en js/, pages/ o blog/.

4.5 Formularios

  • Contacto: añadir Cloudflare Turnstile al formulario y enviarlo a un Worker propio que valide el token, aplique un límite por IP (binding de rate limiting, p. ej. 5 envíos / 10 min) y reenvíe a Apps Script con un secreto compartido. La URL de Apps Script deja de estar en el cliente.
  • Mantener el campo trampa; el Worker descarta en silencio los envíos que lo rellenen.
  • Apps Script: comprobar el secreto compartido y rechazar campos de más de 500 caracteres; anteponer ' a valores que empiecen por =, +, - o @ (inyección de fórmulas en Sheets).

4.6 Pedidos por WhatsApp

El navegador no es fuente de verdad. Control documentado: antes de confirmar un pedido, Lameyer comprueba cada SKU, precio y stock contra public/db/productos.json (o la base de datos real), nunca contra el texto del mensaje. Cuando haya pago en línea, el importe se calcula en el servidor.

4.9 Después de la puerta: Supabase e IAM

Sin cambios respecto al documento 5 §8: clave publicable en el cliente solo con RLS en todas las tablas; clave secreta solo en secretos de Worker o de entorno de GitHub; contraseña de la base de datos en el gestor de contraseñas; token de la CLI solo en el equipo de la persona; migraciones revisadas y aplicadas por CI con revisor obligatorio; dos miembros con MFA; proyectos de staging y producción separados.
