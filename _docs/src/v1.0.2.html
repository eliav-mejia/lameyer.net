Release 1.0.2 — Components shop + terms

/pages/components/ becomes a spare-parts shop with a WhatsApp checkout; new /pages/terminos/ and shared js/tienda.jsx.
Version1.0.2
Date2026-10-03
StackReact 18 UMD · Babel standalone · Tailwind CDN
StatusPre-launch (placeholders open)

1Summary

The old UI-component library at /pages/components/ is replaced by a shop of 30 spare parts in six categories (Oficina, Estudiante, Dev, Redes, Gamer, Otros). Visitors filter, search, sort, add to a cart and send the order as a pre-filled WhatsApp message to +34 602 55 76 85. Prices are stored and charged in EUR (VAT included) and shown for reference in USD, MXN, GBP and ILS using European Central Bank rates. A new terms page covers the seller, returns (30 days), legal withdrawal (14 days), the 3-year guarantee, data protection and a withdrawal form.

4Features

4.1 Catalogue view

  • Category chips; the choice is written to ?cat=<id> with history.replaceState, so categories are linkable. Unknown values fall back to todos.
  • Search is a case-insensitive substring match on name + compat. No hit shows a “Pedir por WhatsApp” link with the query.
  • Sort: featured (array order), price ascending/descending, name (localeCompare(…, 'es')).

4.2 Currencies — useCurrency()

const RATES_URL = 'https://api.frankfurter.dev/v1/latest?base=EUR&symbols=USD,MXN,GBP,ILS';
// returns { currency, setCurrency, format(eur, target?), ratesDate }
  • Starts with fallback rates hard-coded in CURRENCIES, then replaces them with the live ECB rates when the fetch succeeds; any failure keeps the fallbacks silently.
  • Non-EUR amounts are prefixed ≈ and formatted with the ISO code (MXN 821.17) so pesos and dollars cannot be confused; the EUR charge is always shown beside them.
  • The selected currency persists in localStorage['lm-currency'].

4.3 Cart and checkout — CartDrawer

  • Cart is { [productId]: qty }, quantity capped at 99, persisted to localStorage['lm-cart']. On load, ids no longer in PRODUCTS are dropped.
  • store.get/set wrap localStorage in try/catch, so private mode or blocked storage only loses persistence.
  • Checkout requires: at least one line, a name, delivery (Envío en España with a 5-digit postcode, or Recogida en Madrid) and the terms checkbox.
  • The order is a text message: lines, EUR total (plus the reference currency), name, delivery and the terms URL, sent to wa.me/${SELLER.whatsapp}. Shipping costs are confirmed in the chat before payment.
  • The drawer is a role="dialog" with aria-modal; focus moves to the close button and Esc closes it.

4.4 Terms page

Eleven anchored sections (#vendedor … #formulario) linked from each product card, the cart and the footer. Values from SELLER and RETURN_ADDRESSES that still start with [ are rendered in an amber <mark> so they are visible before launch.

5Known issues and limits

5.1 Launch blockers. SELLER.name, nif, address and both RETURN_ADDRESSES are still [...] placeholders, and catalogue prices are not final. Spanish consumer law requires the seller's identity on the terms page before selling.
  • 5.2 Catalogue in HTML. PRODUCTS and CATEGORIES are code inside the page. Editing stock or prices means editing JSX; there is no stock field yet.
  • 5.3 Client-side only. Products are rendered by React in the browser, so the delivered HTML contains no product names or prices: weak for search engines and no Product structured data.
  • 5.4 In-browser compilation. Babel standalone transpiles ~1,000 lines of JSX on every page view, and the Tailwind Play CDN generates CSS at runtime. Both are documented as not for production.
  • 5.5 Rates request on every visit. No caching of the ECB rates (they change once per working day).
  • 5.6 Orders are not recorded. The only record of an order is the WhatsApp chat; prices in the message are whatever the client computed.
  • 5.7 Postcode check accepts any 5 digits (e.g. 00000, or codes outside Spain's 01–52 provinces).
